The core idea

The proctor is the dungeon master. Gauntlet is the rulebook, the map, and the screen.

Tabletop exercises live or die on the facilitator. A great one keeps the scenario plausible, adapts injects to what the room actually does, adjudicates outcomes fairly against the real environment, keeps time, and captures every decision so the debrief writes itself. Most facilitators do this from a static Word document and their own memory.

Gauntlet gives the proctor a control surface for that job. You feed it the exercise environment. It generates a plausible, branching scenario grounded in that environment. As the exercise runs, it presents the next move, offers the branches, rules on player actions against the defenses you defined — and lets the proctor override any of it, because the human is always the final authority. Every choice is logged to an immutable timeline that becomes the after-action report.

Choose-your-own-adventure

Branching, not linear

Injects fire on conditions and player decisions, not just a clock. The proctor sees the branches and picks — or writes a new one on the spot.

Grounded

Bound to your environment

Outcomes are adjudicated against the assets, controls, and detections you fed in — so the scenario stays realistic, never freelance fiction.

Accountable

Everything is evidence

A tamper-evident timeline records injects, decisions, timings, and observations — the raw material for an audit-grade report.

Lifecycle

Seven phases, one continuous loop.

Gauntlet follows the exercise lifecycle practitioners already trust (FEMA HSEEP, NIST SP 800-84), so its artifacts map to what exercise directors and auditors expect. The numbering is real — each phase feeds the next, and phase 7 feeds phase 1 of the following exercise.

The spine

The MSEL is the adventure. The inject is the scene.

A Master Scenario Events List is the facilitator's script — the ordered set of events that drive an exercise. In Gauntlet an inject is one scene: a piece of information delivered to the room, an expected participant action, and a set of branches that decide what happens next. Branches fire on the game clock, on a condition in the environment, or on the proctor's judgment of what the players did. That is the choose-your-own-adventure structure, expressed as data.

# One inject in the Master Scenario Events List
inject:
  id: "INJ-04"
  sequence: 4
  title: "EDR flags LSASS access on FIN-APP-02"
  channel: edr_alert        # email · chat · ticket · siem_alert · phone · news
  visible_to: [blue_cell, white_cell]   # fog of war per cell
  clock: "T+00:35"            # game time, real or compressed
  narrative: "Defender for Endpoint raises a medium alert: a
    non-standard process read LSASS memory on the finance app host."
  expected_actions:
    - "Triage the alert against the IR playbook"
    - "Check whether the host is a crown-jewel dependency"
  maps_to:
    attack: ["T1003.001"]     # OS Credential Dumping: LSASS
    objective: "OBJ-2 Detection & triage"
  branches:
    - when: action_taken       # players isolate the host
      trigger: "isolate_host"
      goto: "INJ-05a"          # attacker pivots, slower
    - when: timeout            # no action within 10 game-minutes
      after: "PT10M"
      goto: "INJ-05b"          # attacker reaches domain admin
    - when: proctor_choice       # DM overrides with a custom turn
      goto: "INJ-05c"

The engine that makes it credible

Adjudication: does the attack succeed here?

When the room takes an action — or the adversary makes a move — Gauntlet rules on the outcome against the defenses you fed it, rather than inventing a result. A technique against a segment with tuned EDR and full logging plays out differently than the same technique against an unmonitored flat network. The proctor always sees the reasoning and can override the ruling; the model proposes, the human disposes.

Action
A player move or an adversary TTP mapped to ATT&CK
→
Environment
Controls, detections & deception on the affected asset
→
Ruling
Detected / missed, time-to-detect, and the branch to take
  • Rules first, judgment always. A transparent rules engine scores detection likelihood and latency from the mapped control coverage; the proctor confirms, edits, or overrides every ruling.
  • Deception is first-class. Honeypots and canaries you defined (mapped to MITRE Engage) can be tripped — a ruling can reveal the adversary early and hand the blue cell an advantage.
  • Explainable. Every ruling records which control caused which outcome, so the after-action report can point at the exact detection gap.

Guardrails

What we build in from day one.

  • Authorization and rules of engagement are exercise metadata, surfaced everywhere. Real-time modes that could touch production stay gated behind explicit scope.
  • "This is an exercise" framing and a facilitator pause control — the psychological-safety, no-fault posture that good tabletops require.
  • Tamper-evident timeline. The exercise record is append-only and hash-chained, so a report is defensible for audit.
  • Defensive scope for generated content. Adversary TTPs are generated only to design an exercise against an environment the user has supplied and is authorized to test — never as operational guidance against systems the user doesn't own.

Roadmap

Tabletop first, then out to the range.

The tabletop core carries the highest value per unit of effort and contains every concept the other modes reuse. Later modes extend the same MSEL, adjudication engine, and reporting — they don't replace them.

In this build

What the first slice actually ships.

A self-contained, runnable product — no dependency on any other system — that proves the loop end to end with a worked example.

  • A domain API (FastAPI + SQLAlchemy) for environments, scenarios, injects, sessions, observations, and reports.
  • The branching MSEL engine — advance a session, evaluate branch conditions, and route to the next inject.
  • The adjudication service — rule a player action against the environment's control coverage, with an explainable result and proctor override.
  • The facilitator console — the DM's screen: current inject, branches, adjudication, game clock, and observation capture.
  • A worked example — a seeded finance-sector ransomware tabletop with objectives, a full MSEL, and a defined environment.
  • Report generation — an After-Action Report drafted from the session timeline.
